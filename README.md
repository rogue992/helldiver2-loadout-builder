# 헬다이버즈 2 로드아웃 빌더

출격 전에 "오늘 뭐 들고 나가지"를 정리하는 개인용 웹 도구. 스트라타젬 4슬롯에 **후보를 슬롯당 1~4개씩** 깔아 두고 실제 선택은 구축함에서 한다.
스펙 비교는 하지 않는다(그건 wiki.gg). 구성 규칙 경고 · 보유 채권 필터 · 종족/팩션별 저장 · 드래그 정렬에 집중한다.

- 사이트: https://rogue992.github.io/helldiver2-loadout-builder/
- 백엔드 없음. 저장은 브라우저(localStorage). 기기 간 이동은 JSON 내보내기/가져오기.

## 사용법

| 하는 일 | 어디서 |
|---|---|
| 기본 로드아웃 | 목록의 **기본**은 수호부 지급 구성(SES 기본 로드아웃과 같음: 궤도 정밀 타격 · MG-43 · B-01 · AR-23 · P-2 · G-12)으로 완전히 고정이다. 이름 · 종족 · 장비 · 후보 어느 것도 바꿀 수 없고 초기화 · 삭제도 안 된다. 바꾸려면 **복제**해서 쓴다. 종족 필터와 무관하게 항상 보인다 |
| 새 로드아웃 | 왼쪽 목록 아래 **신규 배정**. **전선 미지정** 허가서가 열리고, 슬롯을 덮은 관문(또는 허가서의 종족 칸)에서 종족을 고르면 그때 목록에 발급된다. 상단 바가 다른 종족을 보고 있었으면 필터도 고른 종족으로 넘어간다. 고르지 않고 다른 허가서를 열면 아무것도 남지 않는다 |
| 스트라타젬 후보 | 슬롯 오른쪽 위 `1 2 3 4`로 후보 칸 수를 정하고, 칸이나 타일을 누르면 **스트라타젬 선택 창**이 열린다. 창 위쪽 슬롯 4개 중 노란 테두리가 현재 대상이고 눌러서 바꿀 수 있다. **찬 칸(2×2의 한 칸 포함)을 누르고 고르면 그 칸이 교체**되고, 빈 칸은 어느 것을 눌러도 앞에서부터 채워진다. 고르면 다음 빈 칸으로 자동 이동하고, 다 채워도 창은 열려 있다(같은 아이템은 4슬롯에 1번만). 해제는 빌더 타일이나 선택 창 타일의 오른쪽 위 ✕이고, 뒤 후보가 앞으로 당겨지며 대상은 빈 칸으로 간다. 칸을 줄이면 뒤 후보부터 빠진다. 선택 창의 슬롯 이름 옆 `1 2 3 4`로도 칸 수를 바꾼다(같은 값. 늘리면 새 빈 칸이 바로 대상). 선택 창 순서는 나무위키 스트라타젬 문서 순서(공격 → 방어 → 보급, 묶음 안은 목차 순) |
| 즐겨찾기 | 선택 창 카드 오른쪽 아래 별. 열린 허가서의 종족마다(전체 포함) 따로 모인다. 전체 탭 맨 위 **즐겨찾기** 묶음에 모이고, 아래 각 묶음과 종류 탭에서도 맨 앞(종족색 띠)에 온다. 탭 · 묶음 제목의 별 숫자는 그 안의 즐겨찾기 수. 스트라타젬 · 방어구 · 무기 모두 같다. 설정과 함께 저장 · 내보내기된다 |
| 목록 접기 | 맨 위 왼쪽 ☰(저장 목록 서랍의 머리). 접으면 왼쪽 서랍이 사라지고 본문이 넓어진다 |
| 복제 · 삭제 | 목록 카드 오른쪽 위 ⋯ 메뉴(복제 · 삭제), 또는 허가서 하단 삭제 버튼. 삭제는 묻지 않고 바로 지우며 5초 안에 토스트의 **되돌리기**로 원래 자리에 복구한다. 편집 중이던 것을 지웠다면 저장 안 한 편집까지 그대로 다시 열린다. 기본 로드아웃은 복제만 |
| 개인 장비 | 박스를 누르면 **개인 장비 선택 창**(방어구 · 주무기 · 보조무기 · 투척무기가 슬롯 탭)이 열린다. 고르면 다음 빈 장비로 넘어가고(검색어는 비워진다), 다 채워도 창은 열려 있다. 해제는 박스 제목 줄이나 선택 창 타일의 ✕ |
| 저장 | 오른쪽 **수호부 출격 허가서**의 저장. 저장 전 편집은 초안으로 남고 새로고침해도 유지. 저장 안 한 편집이 있는데 목록의 다른 카드를 열거나 신규 배정을 누르면 **저장 후 이동**(기본, Enter) · 계속 작성(Esc) · 버리고 이동을 묻고, 바꾼 곳(이름 · 종족 · 슬롯 · 장비)을 함께 보여 준다(열린 카드를 다시 누르는 것은 아무 일 없음). 이름을 비우고 저장하면 이전 이름으로 돌아간다 |
| 경고 | 배낭 · 지원무기 후보가 2슬롯 이상이면 **위반**(확정 충돌) 또는 **주의**(고르기에 따라). 일회용(EAT 등)은 설정 **중복 경고에서 일회용 지원무기 빼기**가 켜져 있으면 세지 않고, 일회용과 일반 지원무기를 한 슬롯에 섞으면 일회용을 고르면 겹치지 않으므로 주의다. 이글은 3개(설정에서 2개) 이상. 스트라타젬 4슬롯을 다 채웠는데 배낭이나 지원무기가 없으면 **주의**(배낭 없음 · 지원무기 없음), 고르기에 따라 빠질 수 있으면 미확정과 그것을 줄 수 있는 슬롯 번호. 배낭형 지원무기(오토캐넌 등)는 둘 다 채운 것으로, 일회용은 지원무기로 친다. 주의는 도장을 막지 않는다 |
| 도장 | 전부 비어 있음 → 없음, 위반 있음 → **반역 적발**(빨강), 빈 슬롯 있음 → **승인 보류**(노랑), 8슬롯 배정 + 위반 없음 → 저장하면 **진리부 승인**(초록). 저장 전에는 승인 보류로 남는다. 기본 로드아웃은 항상 진리부 승인 |
| 종족 · 팩션 | 맨 위 줄은 목록 필터. 로드아웃의 종족 · 팩션은 허가서 안에서 바꾼다. 종족을 **전체**로 두면 종족 무관 로드아웃(노란색)이 되어 어느 필터에서도 보인다. 넓은 화면에서 맨 위는 한 줄이고, 팩션 칩이 다 안 들어가면 칩 줄을 가로로 밀거나 그 위에서 마우스 휠을 굴려 나머지를 본다(끝이 흐리면 더 있다는 뜻). 그보다 좁은 창에서는 종족 탭과 팩션 칩이 아랫단으로 내려가 2단이 되고, 폰에서는 감긴다 |
| 테마 | 오른쪽 위 크레딧 왼쪽의 미니 화면 2개(줄무늬 콘솔 · 텔레타이프) |
| 보유 채권 · 경고 기준 · 이름 표기 | 오른쪽 위 **설정**. 보유 채권 칩은 채권마다 표지 색이고, **전부 보유** / **초기화**(헬다이버 출동!만) 버튼으로 한 번에. 미보유 채권(과 설정에서 뺀 슈퍼 스토어) 아이템은 선택창에서 숨기지 않고 각 묶음 뒤쪽에 흐리게 보이며, 선택은 가능 |
| 아이템 wiki 보기 | 타일 우클릭(폰은 길게 누른 뒤 손을 뗄 때 열린다) |
| 브리핑 뷰 | 허가서의 **브리핑**. 텍스트 없이 큰 타일만. 세컨드 모니터 · 폰용 |
| 내보내기 | **JSON 내보내기/가져오기**(전체, 설정 패널) · **이미지**(PNG, 허가서 버튼. 슬롯과 허가서를 함께 찍는다) |
| 새 아이템 | 데이터에 새로 들어온 장비 · 스트라타젬은 30일 동안 선택 창 카드 왼쪽 위에 **NEW**가 붙고, 그 아이템이 든 탭에 노란 점이 찍힌다. 새 채권은 설정의 보유 채권 칩에도 NEW. 새 채권은 처음에 보유로 잡히니 미보유면 칩을 눌러 끈다 |
| 신규 채권 공고 | 새 채권이 들어온 뒤 처음 열면 **수호부 보급 공고**(표지 · 채권 구성품 · 같은 날 들어온 아이템 · 이 채권 보유 스위치)가 한 번 뜬다. 어떻게 닫아도 본 것으로 기록되어 다음 채권이 나올 때까지 다시 뜨지 않고, 설정의 보유 채권 오른쪽 **최신 채권 공고**로 다시 연다. 저장 기록이 없는 첫 방문에는 띄우지 않는다 |
| 버전 | 화면 오른쪽 아래(좁은 화면은 페이지 맨 끝)의 `v1.0.N`. 배포할 때마다 마지막 숫자가 오른다. 마우스를 올리면 빌드 커밋 · 날짜 · 데이터 패치가 보인다 |

가져오기는 형식을 검사한다. 식별할 수 없는 로드아웃이 하나라도 있으면 파일 전체를 거부하고, 종족 · 칸 수 · 날짜처럼 어긋난 필드는 안전한 값으로 보정한다. **병합**은 열린 초안을 건드리지 않는다. **설정도 가져오기**는 파일마다 새로 체크한다.
**교체**를 고르면 직전 상태를 브라우저 안(`hd2lb.backup`) + JSON 다운로드로 백업한 뒤 바꾼다. 설정의 **마지막 백업 복원**으로 되돌릴 수 있고, 복원도 전체 교체라 항상 확인을 거친다.
메인 화면을 탭 두 개에 띄우고 양쪽에서 편집하면 마지막 저장이 이긴다. 브리핑 뷰를 다른 탭에 띄우는 것은 안전하다.
화면을 그리다 오류가 나면 복구 화면이 뜬다. **편집 중인 허가서 버리고 다시 열기**나 **저장 기록 내려받기**(가져오기 형식)로 기록을 살릴 수 있다.

## 개발

```bash
npm ci
npm run dev          # http://localhost:5173/helldiver2-loadout-builder/
npm run typecheck    # tsc -b --noEmit (app · node · scripts · test)
npm run lint:copy    # 문구에 em dash 금지
npm run lint:theme   # 테마 셀렉터 위치 검사
npm test             # 단위 테스트(tsx --test, Node 내장 러너): 경고 판정 · 선택 창 칸 이동 · 바꾼 곳 · 값 보정 · NEW 판정 · 스트라타젬 순서표 · 채권 색표 · 신규 채권 공고 · SVG 검사 · id 규칙
npm run build        # dist/
```

스택: Vite + React 19 + TypeScript · zustand(persist) · @dnd-kit · html-to-image. Node 24(`.nvmrc`).
`main` push가 GitHub Actions로 Pages에 배포된다(레포 Settings → Pages → Source = GitHub Actions 1회 설정). 배포 전에 typecheck · lint 2종 · 테스트를 돌리고, 하나라도 실패하면 배포하지 않는다.

화면 버전은 `major.minor.patch`다. major.minor는 `package.json`의 `version`에서 손으로 올리고, patch는 그 `version` 줄을 마지막으로 바꾼 커밋 뒤에 쌓인 커밋 수를 빌드할 때 git으로 센다(`vite.config.ts`). 그래서 `main` push(배포)마다 저절로 오르고, minor를 올리면 0부터 다시 센다. CI는 이 수를 세려고 전체 기록을 받는다(`fetch-depth: 0`). 로컬 개발 서버에서는 `-dev`가 붙는다.

## 데이터 갱신

아이템 데이터와 아이콘은 `public/data`, `public/icons`에 **커밋된 정적 파일**이다. 게임 업데이트가 나오면 Claude Code에서 `/update-data`를 실행한다
(`.claude/skills/update-data/SKILL.md`). 요약:

1. `npm run data:fetch` : wiki.gg Cargo 5테이블 수집(1.5초 간격, API만) + diff
2. `npm run data:build -- --dry-run` : counts · missingKo · unknownSource 확인
3. 새 아이템 한글명 · 분류를 `data/overrides/ko.json` · `manual.json`에 기록(사용자 확인). 새 스트라타젬은 `src/data/stratOrder.ts`의 나무위키 자리에 id를, 새 채권은 `src/data/warbondColors.ts`에 표지에 맞는 색을 넣는다(빠지면 테스트가 실패한다)
4. `npm run data:build -- --assign-n --label <패치>` → `npm run icons:fetch`(아이콘 · 렌더 · 채권 표지) → 재빌드. 새 아이템은 번호와 함께 그날 날짜를 받아 30일 동안 NEW로 보이고, 새 채권은 다음 방문에 신규 채권 공고로 뜬다
5. 검증 후 커밋 · 푸시

스트라타젬 아이콘의 출처(nvigneux)는 커밋 SHA로 고정돼 있고, 받은 SVG에 스크립트 · 이벤트 속성 · 외부 참조가 있으면 저장하지 않는다. `data:seed`는 1회성이라 `ko.json`이 있으면 `--force` 없이는 덮어쓰지 않는다.

`data/registry.json`(아이템 번호표 `n`과, 첫 수집 뒤에 들어온 아이템이 번호를 받은 날 `added`. 앱은 직접 읽지 않고 `items.json`의 `n` · `addedAt`으로 받는다)과 아이템 `id` 규칙은 계약이다. 둘 다 덧붙이기만 하고, `id` 규칙을 바꾸면 기존 저장본이 깨진다.

## 표기 규칙

- 종족: **테르미니드 · 오토마톤 · 일루미닛**. 팩션은 종족별 기본 + 변종 3.
- 부처: 군사 · 장비 · 출격 허가 = **수호부**, 판정 · 선전 · 재교육 = **진리부**. "국방부"는 쓰지 않는다.
- 모든 문구에 em dash(U+2014) 금지. `npm run lint:copy`가 검사한다.
